JSONing provides open-source software for mocking REST APIs from JSON resources. You can run the official project locally, control its test data, and simulate errors before your real backend exists. A hosted read-only sample endpoint is also available. The custom-generator web page returned an internal server error during this review, so hosted creation should not be assumed to work.

## What the free plan gives you

The official JSONing API repository provides the source under the MIT license. Its README describes local installation, JSON resource configuration, CRUD routes, pagination, and custom response rules. A local mock can be useful in a classroom, a frontend prototype, or an automated test suite without depending on a hosted generator.

Put resources in a single JSON object containing arrays of records. The local server exposes CRUD routes, with page and limit parameters for pagination.

Rules match a request's method, path, headers, or payload and adjust response status, headers, or body. Read the project's rule ordering and stop behavior when combining them.

The hosted public products endpoint returned sample JSON without authentication during this review. It is a read-only demonstration, so use the local version when tests need to create or modify data.

## When you hit a limit

There is no published hosted request allowance in the available documentation. Earlier website documentation asked users to limit calls, suggested local hosting for heavier use, and described daily deletion of custom hosted APIs. Those statements do not establish that the currently unavailable generator can create a new API today.

A local installation uses your own machine's resources and lifecycle. Keep fixtures under your control and reset the mock as tests require. The repository does not provide a hosted uptime promise or a billing policy for the unavailable generator; no strict hosted cap is confirmed here.

## Gotchas

- The custom-generator page returned a server error on October 21, 2026. This entry's usable routes are the read-only demo and official local software.
- A public demo cannot hold changing test state. Keep private fixtures and credentials out of public requests.
- Mock responses test frontend assumptions; they do not prove that the eventual production backend behaves identically.

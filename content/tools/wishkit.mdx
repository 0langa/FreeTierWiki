WishKit gives an app developer one place to collect feature requests and talk with users. The free version fits a project that wants to test whether feedback comes through the app, or to see the first set of requests before deciding how to manage them.

## What the free plan gives you

Free includes one project and no card. The comparison table says the first five feature requests and first five conversations are visible. There is no user count limit for people who submit and vote, so account for the visibility constraint separately when planning a rollout. Free can read App Store reviews. It also limits the MCP connection to the first five feature requests, which can be useful when testing an assistant workflow around the feedback. If you already use another issue tracker, decide which requests you want to act on before transferring them into that backlog.

## When you hit a limit

The pricing FAQ says WishKit stores requests beyond the first five and unlocks them if you upgrade. A larger user base can produce more requests than the free view lets you inspect. Before inviting all users to a board you intend to use for routine triage, check what you can see in the dashboard. WishKit lists a flat plan price for an upgrade.

## Gotchas

- The number of users who submit and vote is separate from the number of feature requests you can see.
- A project is one feedback board with its own API key. An app and its website can share that board; a second separate board requires a paid plan.
- The free App Store review feature is for reading. Check plan requirements for managing replies.

## Questions people ask

### How many apps can I add?

The Free comparison table allows one project.

### Will I be charged per person who votes?

The provider lists unlimited users on Free and does not price the plan per user.

### Can I see every request?

The Free table describes visibility into the first five. Check the paid options when you need the rest of the backlog in view.

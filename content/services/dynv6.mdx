dynv6 is a free dynamic DNS service run by Digineo GmbH. It gives public hostnames to machines with changing IPv4 and IPv6 addresses within seconds, and it is built around how IPv6 prefixes change.

## What the free plan gives you

The home page says dynv6 is free for everyone. You can choose a free hostname to start, or delegate your own domain to dynv6. It combines your devices' MAC addresses or host IDs with your dynamic IPv6 prefix, so every host on a network keeps a public name when the prefix changes, without NAT or port forwarding.

Updates can come through a REST API, an update API, the DynDNS API, SSH with public key authentication, or DNS updates signed with TSIG keys. Webhooks can update other services whenever your IP address changes. The docs note that any RFC2136-compliant software works, including lego and Caddy for free Let's Encrypt certificates.

## When you hit a limit

The fetched pages do not state a limit on hostnames, zones, or update frequency, and there is no paid plan to move to. The real limit is the one dynv6 states itself: it does not offer enterprise-grade DDoS protection or SLAs yet, and it says not to use it for critical services.

Some APIs have narrower scope. The DynDNS-compatible API can only update the IPv4 address of a zone, so for IPv6 you use the update API with ipv6=auto, ipv6prefix, or 6to4. TSIG updates are rejected if the zone in the update does not match the key.

## Gotchas

- With nsupdate, a blank line acts as a send command, so a script with blank lines between statements will likely fail.
- Each zone has its own HTTP token, so keep it out of public scripts.
- There is no SLA, so a dynv6 outage takes your hostnames down with no recourse.

## Questions people ask

### Is dynv6 free?

Yes. The home page says it is free for everyone and that dynv6 is a free service by Digineo GmbH.

### Can I use my own domain with dynv6?

Yes. You can delegate your own domain to dynv6 instead of using a free hostname.

### Should I use dynv6 for a production service?

dynv6 says not to use it for critical services, because it does not offer enterprise-grade DDoS protection or SLAs yet.
